# 截面因子挖掘性能优化总结（2026-04-17）

本文总结本次针对“截面GP / 截面RL”挖掘耗时问题实施的优化改动，覆盖数据加载、表达式评估、去重缓存、向量化和并行化等环节。

## 1. 优化目标与场景

- 目标场景：`50` 个币种，`5` 个月，`1h` 周期。
- 目标问题：截面因子挖掘耗时过长，尤其在 `GP` 进化评估与 `RL` 训练/后处理阶段。
- 优化原则：
  - 减少重复计算（缓存、去重）
  - 降低 Python/Pandas 循环开销（向量化）
  - 利用并发能力（数据加载、可配置并行评估）
  - 尽量保持现有接口兼容

## 2. 本次改动文件

- `factor_miner/core/gp_miner.py`
- `factor_miner/core/rl_miner.py`
- `webui/routes/mining_api.py`

## 3. GP（遗传编程）优化明细

### 3.1 截面评估向量化（替代逐行构表 + groupby）

- 位置：`GPMiner._evaluate_cross_sectional`
- 旧逻辑：
  - 逐 symbol/逐 time 构造 `all_rows`；
  - `DataFrame.groupby('date')` 循环计算 IC/RankIC。
- 新逻辑：
  - 按 symbol 拼接为 `factor_df` 与 `ret_df`；
  - 对齐索引后转 `numpy` 矩阵逐期计算；
  - 降低对象创建与 groupby 开销。

### 3.2 表达式评估缓存（代际复用）

- 位置：`GPMiner.mine`
- 新增：`self._eval_cache: Dict[str, Dict]`
- 行为：
  - 以表达式字符串 `to_string()` 作为 key；
  - 相同表达式不重复做截面评估。

### 3.3 Rank 计算轻量化

- 位置：`GPMiner._evaluate_cross_sectional`
- 旧逻辑：`pd.Series(...).rank(...)`
- 新逻辑：`np.argsort(np.argsort(...))` 计算秩，再换算百分位。
- 影响：减少 Pandas 临时对象开销。

### 3.4 子树级 memoization（单个体内复用）

- 位置：`GPMiner._evaluate_node`、`GPMiner._evaluate_individual_on_symbol`
- 新增：节点缓存 `node_cache`（按节点对象 id）。
- 行为：
  - 同一个表达式树内重复子树仅计算一次；
  - 在 feature/constant/operator/异常分支均缓存结果。

### 3.5 多样性筛选中的候选因子缓存

- 位置：`GPMiner._select_diverse_best`
- 新增：`factor_series_cache`
- 行为：
  - 候选表达式在各 symbol 上的因子序列只计算一次；
  - 后续比较复用缓存。

### 3.6 多样性相关性计算改为 numpy 快路径 + 早停

- 位置：`GPMiner._select_diverse_best`
- 旧逻辑：`pandas corr`
- 新逻辑：
  - `numpy` 向量中心化后手工算相关；
  - 平均绝对相关超过阈值时提前停止比较。

### 3.7 单代评估“表达式去重 + 可配置并行”

- 位置：`GPMiner.mine`
- 新增配置：`eval_workers`（默认 `1`）
- 行为：
  - 每代先按表达式聚类，同表达式只评估一次；
  - 未命中缓存表达式可通过线程池并行评估；
  - 评估结果回填到同表达式的所有个体。

## 4. RL（强化学习）优化明细

### 4.1 训练 step 内奖励缓存

- 位置：`RLMiner.mine`
- 新增：`reward_cache`
- 行为：
  - 同一步内重复公式不重复执行 `vm.execute + bt.evaluate`。

### 4.2 Top 公式收集：采样化 + 去重化

- 位置：`RLMiner._collect_top_formulas`
- 旧逻辑：`argmax` 生成，重复率高。
- 新逻辑：
  - 使用分布采样 `Categorical(logits=...)`；
  - 支持 `temperature` 与 `top-k` 过滤；
  - 对采样结果先去重再评估；
  - 避免重复加入已存在公式。
- 新增配置：
  - `collect_temperature`（默认 `1.0`）
  - `collect_top_k`（默认 `0`，不限制）

### 4.3 数据准备阶段向量化对齐

- 位置：`RLMiner._prepare_data`
- 旧逻辑：按 symbol/col/date 三重循环填数组。
- 新逻辑：
  - 统一日期索引 `reindex`；
  - 缺列补 0，缺值 `fillna(0)`；
  - 分列 `np.stack` 后转 tensor。

### 4.4 多样化筛选阶段缓存与相关性快算

- 位置：`RLMiner._diversify_formulas`
- 新增：
  - `formula_eval_cache`（公式级执行与评估结果缓存）
  - 归一化向量 `_normed_vector` 用于快速相似度比较
- 旧逻辑：每次 `torch.corrcoef(torch.stack(...))`
- 新逻辑：归一化后用 `torch.dot` 快速估计相关性并阈值筛选。

## 5. API 层优化明细（GP/RL 共用）

### 5.1 币种数据并发加载

- 位置：
  - `_run_cross_sectional_mining_background`
  - `_run_rl_cross_sectional_mining_background`
- 改动：
  - 串行 `for symbol` 拉数改为 `ThreadPoolExecutor + as_completed`；
  - 提升 50 币种场景的数据准备速度。

## 6. 建议配置（当前优化版本）

### 6.1 GP 推荐

- `population_size`: `64 ~ 100`
- `max_generations`: `10 ~ 15`
- `max_depth`: `3 ~ 4`
- `stagnation_limit`: `3 ~ 5`
- `eval_workers`: `4` 起步（可按 CPU 调整）

### 6.2 RL 推荐

- `train_steps`: `120 ~ 200`
- `batch_size`: `128 ~ 256`（按显存）
- `max_formula_len`: `12 ~ 16`
- `collect_temperature`: `0.8 ~ 1.2`
- `collect_top_k`: `10 ~ 30`

## 7. 验证与回归建议

- 已做语法检查：修改后文件均通过 `py_compile`。
- 建议执行对比实验（同数据同参数）：
  - 数据加载耗时
  - GP 单代耗时 / 总耗时
  - RL 每 100 step 耗时 / 总耗时
  - 结果质量：`IC`、`ICIR`、因子数量、多样性

## 8. 风险与注意事项

- 引入并行评估后，CPU 占用会提高，需根据机器核数调 `eval_workers`。
- 采样式 top 公式收集会提升多样性，但会引入轻微随机性波动。
- 相关性快算路径在数值稳定性上已加基本防护（有限值筛选、标准差下限），仍建议在极端数据下做回归验证。

## 9. 可继续优化方向

- GP：进一步考虑“进程池并行”（规避部分 GIL 影响，需评估序列化成本）。
- RL：对 VM 执行做 batch 化（同结构公式可批量执行）。
- 缓存治理：按代/按会话做容量控制，避免超长任务缓存膨胀。
